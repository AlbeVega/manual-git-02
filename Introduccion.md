## En la primera parte

Veremos el concepto de Git. En esta parte veremos cuáles son sus funciones, veremos que Git es un sistema de control de códigos y nos daremos cuenta de que, más que un sistema, es una herramienta esencial para los desarrolladores. Otra de las cosas que vamos a poder observar es lo fundamental que puede ser hoy en día Git para los desarrolladores web para poder desarrollar una página web, una app u otras opciones del desarrollo, ya que les permite a ellos crear repositorios, ramas y así no cometen tantos errores en los códigos, ya que otros desarrolladores del mismo trabajo le pueden rechazar las líneas de códigos que hayan hecho y así no dañar un proyecto grande de una empresa o propio.

También aprenderemos que Git permite llevar un registro de todos los cambios realizados en un proyecto. Esto facilita saber quién realizó cada modificación, cuándo se hizo y qué cambios fueron realizados. De esta manera, si aparece algún problema, los desarrolladores pueden revisar el historial y encontrar una solución de manera más rápida.

Además, Git permite trabajar en equipo de una forma mucho más organizada. Varios desarrolladores pueden trabajar en diferentes partes de un mismo proyecto sin tener que modificar directamente el código principal. Esto ayuda a mantener el proyecto organizado y facilita la integración de los diferentes cambios.

Otro aspecto importante será conocer la diferencia entre Git y plataformas como GitHub. Git es la herramienta que permite controlar las versiones del código, mientras que GitHub es una plataforma que permite almacenar repositorios de Git en Internet, compartirlos y colaborar con otros desarrolladores.

## En la segunda parte

En esta segunda parte vamos a poder conocer más de los comandos básicos de Git que son: crear repositorios, copiar uno existente, editar líneas de códigos de uno existente que tengan errores, bugs u otra anomalía y volver a subirlo. Vamos a poder entender que hay miles de comandos existentes, pero aun así los antes mencionados son los más básicos y más usados. Vamos a poder conocer algunos de ellos como git init y conoceremos para qué es usado. También conoceremos el comando git clone y su uso, que prácticamente es clonar como su nombre lo dice. Otro código que conoceremos es git config y su uso y así como esos códigos veremos muchos más comandos de Git.

También aprenderemos comandos importantes como git add, que permite preparar los cambios para realizar una confirmación; git commit, que sirve para guardar esos cambios en el historial del proyecto; y git push, que permite enviar los cambios a un repositorio remoto.

De igual manera, conoceremos git pull, que sirve para descargar y combinar los cambios que existen en un repositorio remoto. También veremos git status, que permite conocer el estado actual de los archivos del proyecto, y git log, que permite revisar el historial de cambios realizados.

Estos comandos son importantes porque forman parte del trabajo diario de muchos desarrolladores. Al conocerlos y utilizarlos correctamente, se puede trabajar de una manera más rápida, organizada y segura.

## En la tercera parte

En la tercera parte vamos a aprender las buenas prácticas de Git, que prácticamente nos dice que Git no debe entenderse como un sitio de almacenamiento de códigos, sino como un control de versiones de códigos y revisión automática. Veremos que si aplicamos bien Git prácticamente mejoraremos en los proyectos y cometeremos menos errores, ya que:

Es más seguro para los nuevos desarrolladores.
Es más seguro para los proyectos.
Es más sencillo de revisar.
Veremos que es menos propenso a cometer errores.

Algunas estructuras habituales son:
 
Mi_proyect/
src/
tests/
docs/

Y, por último, uno de los más usados que es _GitHub_.

También aprenderemos la importancia de realizar commits claros y organizados. Un buen mensaje de commit debe explicar de manera sencilla qué cambio se realizó. Esto permite que los demás integrantes del equipo puedan entender fácilmente el historial del proyecto.

Otra buena práctica consiste en evitar subir archivos innecesarios al repositorio. Para esto se puede utilizar el archivo .gitignore, que permite indicar qué archivos o carpetas no deben ser incluidos en el control de versiones. Esto ayuda a mantener los repositorios limpios y evita compartir información que no debería estar dentro del proyecto.

También es importante mantener actualizado el repositorio antes de comenzar a trabajar, especialmente cuando varias personas están participando en el mismo proyecto. De esta manera se reducen los conflictos y se trabaja sobre una versión más reciente del código.

### Trabajo con ramas

Ya en lo últimos encontraremos los trabajos con ramas. Prácticamente esto nos dice que cuando trabajamos en un proyecto usando GitHub, las ramas son unas herramientas de ayuda para los programadores, ya que así cada quien trabaja por separado y no dañan el proyecto original.

Nos dice también que una rama se entiende como una copia o una línea independiente de desarrollo del proyecto original y con esta copia vamos a poder editar el proyecto sin afectar directamente la versión principal. Cuando los cambios están terminados y han sido revisados, pueden integrarse nuevamente al proyecto principal.

Algunas de las ramas más comunes pueden ser:

* main: contiene la versión principal y estable del proyecto.
* develop: puede utilizarse para integrar cambios durante el desarrollo.
* feature: se utiliza para desarrollar nuevas funciones.
* bugfix: se utiliza para solucionar errores encontrados en el proyecto.

También aprenderemos que las ramas facilitan el trabajo colaborativo porque cada desarrollador puede trabajar en una función diferente. Después, los cambios pueden ser revisados antes de incorporarlos a la rama principal.

### Flujos de trabajo

Veremos los flujos de trabajo que son:

Crear una rama.
Hacer cambios.
Guardar los cambios mediante commits.
Publicar la rama.
Revisar los cambios.
Corregir posibles errores.
Integrar los cambios al proyecto principal.
Actualizar la versión local del proyecto.

Estos flujos de trabajo sirven para mantener una organización adecuada durante el desarrollo. Además, permiten que los cambios sean revisados por otros integrantes del equipo antes de llegar al proyecto principal.

Finalmente, veremos que Git y GitHub son herramientas fundamentales en el desarrollo de software moderno. Su utilización permite mejorar la organización, facilitar el trabajo en equipo, controlar los cambios y reducir el riesgo de perder información o introducir errores importantes en un proyecto.
